fn publishes_float_values(statement: &Expr, field_type: &DataType) -> bool
Expand description

Whether the existing planner publishes a Float64 for field_type under statement.

Anything not proved is false, which declines. Proved, with the existing planner’s deciding site:

  • arithmetic: PromPlanner::prom_token_to_binary_expr_builder wraps operands in cast_float, unless an operand folds before the cast (folds_before_cast),
  • min/max (Extremum) and avg, stddev, stdvar, quantile, group (PromPlanner::create_numeric_aggregate_expr) return Float64,
  • sum returns Float64 for float input and the input type for integers,
  • FLOAT_ANSWERING_RANGE_FUNCTIONS.

Parentheses, subqueries and the selecting aggregates publish their input’s class; a bare selector publishes the field’s own type. Not proved: count/count_values (Int64), math and label functions, -x, comparisons and set operations.
