The native fused-series route of the PromQL planner.

PromPlanner::try_plan_native_fused offers a whole statement expression to the native compiler and, when the compiler accepts it, replaces everything the existing path would plan below the root with one [FusedSeries] node over the selector’s own table scan. A tree that folds across series, such as an aggregate, is split instead: its per-series prefix and a Partial aggregate run in a FusedSeries producer, a SeriesRepartitionExec routes that state, and a second FusedSeries runs the Final aggregate over it, because a region holds only part of a group. Declining is the normal answer: every shape the compiler does not accept, and every query this route cannot bind to a scan faithfully, keeps the plan the existing planner builds.

The node is built from the raw series schema the tree’s input was compiled against, the statement’s evaluation grid, and output tag names derived from the native tree. The output schema has the shape the existing unary pipeline produces – the time index, then the series fields, then the tags – so a node planned here is consumed by the same code that consumes a SeriesNormalize output.

A statement that reads no data - a constant, time(), vector(time()) - is planned with no scan: one node, no child, the time index and value.
