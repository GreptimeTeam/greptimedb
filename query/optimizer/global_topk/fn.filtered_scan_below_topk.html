pub(crate) fn filtered_scan_below_topk(
    sort: &SortExec,
    partitions: usize,
) -> Result<Option<&RegionScanExec>>
Expand description

Returns the region scan that sort reads if sort is a TopK on the time index with a fetch up to MAX_GLOBAL_TOPK_FETCH, reading the scan through row-wise operators that include at least one filter, and if the scan has more ranges than partitions.

Without a filter every scanned row reaches the heaps, so each fills at once. On another sort key the scan cannot skip ranges by time, so one heap only serializes the work. A filter with a fetch keeps the first rows that pass, so reading ranges in another order would change which rows it keeps. With at most one range per partition the threshold leaves no later range to skip, so one heap only adds a single consumer.
