Module copy_in 

Source
Expand description

PostgreSQL COPY ... FROM STDIN (copy-in) support.

The wire handshake is driven by pgwire: returning [Response::CopyIn] from a query handler makes the server send a CopyInResponse and enter the copy-in sub-protocol; subsequent CopyData messages from the client are dispatched to [CopyHandler], whose implementation below parses the data stream incrementally and flushes it into the query handler as [RowInsertRequests] batches.

§Formats

The supported formats are the explicit codec::CopyFormat enum — csv (table-bound, incremental row parsing) and influxdb (table-less, one bounded whole-payload request). Each format states its own target rule and ingestion shape in the match arms of the copy lifecycle below; adding a format is a new variant plus its arms. Builders resolve a FORMAT name (and its aliases) through REGISTERED_FORMATS. See the codec module docs.

COPY_IN_MAX_PAYLOAD_BYTES 🔒
Upper bound of an influxdb COPY FROM STDIN payload. One COPY statement is one bounded ingestion request (the whole payload is buffered like one HTTP write body); a larger import is multiple COPY statements. Streaming ingest may arrive later, with framing owned by the shared line-protocol parser rather than the COPY layer.
REGISTERED_FORMATS 🔒
The registered COPY FROM STDIN formats: accepted FORMAT name to builder. csv is the only implemented format; the others are registered so they report a clear “not supported yet” instead of an unknown-format error.
