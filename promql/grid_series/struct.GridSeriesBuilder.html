Struct GridSeriesBuilder

pub struct GridSeriesBuilder {
    schema: Arc<SeriesSchema>,
    grid: Arc<EvalGrid>,
    next: usize,
    indices: Vec<usize>,
    fields: Vec<FieldBuilder>,
}
Expand description

Builds one grid series from rows pushed at absolute grid indices.

A push names one position and the value each field holds there. Rows are accumulated compactly: a row is kept only when at least one field holds a value at that position, so an empty stretch costs one skipped push and no storage at all. Fields stay row-aligned, so a field with no value at a retained row still gets a null there; the Arrow layout needs one row per retained position, and the position does hold a value.

GridSeriesBuilder::finish hands out all the buffered rows as one [Series], whose [TimeAxis] names the maximal runs of consecutive positions the rows make up. The rows are not densified: the axis says where they sit, so a series over two far-apart positions costs two rows and two spans, not a row per position between them.

A builder serves one series at a time. GridSeriesBuilder::begin_series starts the next one; nothing else resets the series state, so GridSeriesBuilder::take_buffered can hand out the rows gathered so far and let the same series go on.

Fields§

§schema: Arc<SeriesSchema>§grid: Arc<EvalGrid>§next: usize

Smallest index the next push may use.

§indices: Vec<usize>

Grid index of each retained row, ascending.

This vector is the only record of where the gaps are, and it says only where rows sit: with V entries, F fields and k runs (k <= V) the whole series costs 8*F*V value bytes plus validity bits, one usize per retained row and O(k) run descriptors. Nothing is proportional to the positions holding no value.

§fields: Vec<FieldBuilder>

One row per retained row, per field; empty when nothing is buffered.

pub fn has_pending(&self) -> bool

Whether rows have been pushed that no caller has taken yet.

Every hand-out drains the buffer, so “rows buffered” and “rows a caller has not taken” are the same thing: a true here means the next Self::finish or Self::take_buffered has something to return.

Source

pub fn begin_series(&mut self)

Starts the series the following pushes belong to.

This is the only place that resets the series state, so it is the logical-series boundary: Self::finish hands the rows out but resets nothing, and Self::take_buffered deliberately does not reset anything either.

Panics in debug builds when rows are still pending, which means the previous series was left unread.

Source

pub fn take_buffered(&mut self, metric: SeriesLabels) -> Result<Option<Series>>

Hands out every row buffered so far as one series, without ending the series.

This is a prefix flush: the rows pushed since the last hand-out become one [Series] whose axis names the runs they make up. None means nothing is buffered, and the caller may push more rows. Later pushes still belong to the same logical series, so the caller keeps the metric and reads the next hand-out as a continuation rather than as a new series.

Nothing is reset: not the metric, not the index cursor, not the position order. A caller that wants a new series calls Self::begin_series.

Source

pub fn finish(&mut self, metric: SeriesLabels) -> Result<Option<Series>>

Returns the series the pushed rows make up: one [Series] over the runs of consecutive positions that hold a value, or None when no retained row holds one.

The rows share the one buffer per field, so the result costs a span per run and not a row per position between the runs. This ends the logical series; the next one starts with Self::begin_series, which is the only reset.
