The child’s frame schema when the child already publishes this node’s frame.

Such a child needs no decode and no re-encode: publishing each batch under this node’s declaration is the whole job. “This node’s frame” is the canonical frame of these fields with explicit labels and no label decode description, which is what the decode-and-repack path would publish for the same chunks, so the declared ordering is the only difference that can remain - and only downwards. This node declares ORDERING, the weakest per-series promise it keeps, so a child that promises key-then-time already keeps it, while an interleaved child does not: forwarding that one would promise more than the child does.

Anything else - other content, key-encoded labels, a description, a grid, other fields, a metadata entry this node would not write - keeps the batches on the decode-and-repack path.
