pub fn checked_series_stream(
    chunks: SendableSeriesStream,
    raw_ordering: SeriesOrdering,
) -> SendableSeriesStream
Expand description

chunks with the sequence check the frame path runs, applied to each chunk as it arrives.

A consumer that decodes a frame validates the sequence it receives - a chain that never closes, a key that recurs after its final chunk, timestamps that go back across chunks, keys that go back under key-then-time order - because the frame may have been written by another process. pack_raw_series and unpack_raw_series run that check on both ends, and the evaluated packer and unpacker run its evaluated counterpart. A consumer handed the chunks themselves has no frame to decode and no other process to distrust, but the producer can still be wrong: a router publishes what its owners merged, and a second publication of one identity would be as wrong in process as it is across a frame. So the same validators run here, over the same sequence, and the shortcut refuses what the frame would have refused.

A state publication is the one content with no such check to run, on either path: the frame consumer’s state stream decodes each exported row and hands it on, so there is nothing it would refuse that the handover must refuse too. What both paths do enforce is enforced where the row is decoded - in the producer’s handover stream - and this stream passes state rows through.

raw_ordering is the ordering the producer declares for its raw frames - the one a decoding consumer would read out of the frame schema. It is not inferred from the chunks.
