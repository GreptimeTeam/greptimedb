The one metric every input series is named, taken from the binding.

The canonical pass judged a dropped label set by this: a node that drops the metric name is only told to stream when everything below it is named the same one. The execution reads it so the collection it performs at run time is decided by that same proof; None is a binding that names no metric - one raw source per input - and every consumer then collects.

pub fn has_partition_disjoint_identities(&self) -> bool

Returns whether each output series identity is confined to one input partition.

This is true only for a single per-series scan whose bound tags cover its primary key, a raw source that kept that provenance, or another proven fused chain, whose native tree answers every series it reads as that series: an instant selection of the sample or of an info sample, a filtering comparison, a window that keeps the metric name, or a chain of nodes that drop the metric name over a scan that reads one metric and keys its series by labels that survive the drop.

A node that drops the metric name is proved rather than refused outright: a PrimaryKey binding reads one metric, so the name those nodes drop is the one every stored series carries, and what tells two of them apart are the tags the binding names. Requiring the rows to carry those tags, refusing a binding that keys a series by __type__ or __unit__ - which a name-dropping kernel removes with the name - and refusing a binding whose key columns are not every one of them non-nullable, because only a nullable column lets one series hold NULL where another holds '', which such a kernel normalizes into one absent label, is what keeps this an identity of what the tree read. A scan that states none of those facts proves nothing, and a row table that would not carry the tags below it proves nothing either, so both are refused here rather than refined later: the router above a producer that claims CompleteDisjoint stops checking for duplicates, and a refusal only keeps the merging path it would otherwise have taken.

pub fn try_new( promql: Arc<str>, inputs: Vec<(Arc<dyn ExecutionPlan>, RawLabelSource, SeriesOrdering)>, tree: Arc<NativeTree>, output_schema: SchemaRef, time_column: String, tags: Vec<String>, ) -> DataFusionResult<Self>

Creates the node, rejecting whatever this node cannot execute or convert.

input produces native raw series frames: the series’ encoded key, its finality, its timestamps and its fields, plus the complete labels when label_source is [RawLabelSource::Explicit]. time_column and tags name the columns of the output, which is a row table rather than a frame.

The parameters stay separate because each is a fact its own caller has: the query, the plan below, the frame’s label binding and ordering, the tree, and the three things the output schema is classified by. A struct over them would be the same list under another name.

pub fn hands_over_series(&self) -> bool

Whether this node’s output is a publication another native operator can read in process.

fn metrics(&self) -> Option<MetricsSet>

The metrics this node records itself, which is none of its tree’s.

A [MetricsSet] is a flat, name-keyed bag: reporting the tree’s figures through it would attribute every node’s figures to this node, because the reader cannot tell them apart. Each node reports its own on its own line instead - and, as data, through the tree this node registers as [NativeTreeMetric] - so they are left out here and this node reports only what an operator of its own would add.

fn input_distribution_requirements(&self) -> InputDistributionRequirements

No optimizer exchange is requested here: evaluated-input partition counts and window owner routing are normalized explicitly while constructing the physical plan. Raw-input layout is left to its existing execution path.

fn benefits_from_input_partitioning(&self) -> Vec<bool>

Splitting the input further would not help: a second partition is a second set of series answered by a second tree, which this node already runs, and raising the count is what an optimizer does by adding a round-robin exchange that reorders nothing it can rely on.
