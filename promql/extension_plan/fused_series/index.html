Module fused_series 

Source
Expand description

One node that runs a compiled native tree over raw series.

FusedSeries is the logical half: it holds the PromQL text the tree was compiled from, the tree itself and the binding its input was compiled against. FusedSeriesExec is the physical half: it owns one execution of that tree per partition, decodes its input frames into raw series chunks, and converts evaluated chunks back into batches.

Both halves show their own compiled tree in EXPLAIN, rendered by NativeTree’s display. The logical node shows its tree without metrics; the physical node includes each tree node’s recorded metrics when available. The text is what names the value columns, not a plan line: neither half echoes the query.

Scope of this layer: the input is a stream of native raw series frames (raw_series_frame_schema) — one row per chunk, carrying the series’ encoded key, its finality, its timestamps and its fields, plus the complete labels when the frame is explicit — with each series’ rows contiguous and its timestamps ascending, which is what the caller’s [SeriesOrdering] names. The output is one batch per evaluated chunk, with the statement’s grid timestamps in the declared time column. Each source contributes exactly one partition per output partition; this node has no internal gather. Physical planning must normalize global consumers to one partition, and matching locality requires a verified matching-key router on both operands. Everything the tree cannot do is rejected when the execution plan is built, not when the first batch arrives: a tree the native runtime does not execute, a frame whose schema the tree’s input was not compiled against, or an output schema the conversion cannot classify.
