The native PromQL evaluation model.

A query compiles to a plan::NativeTree: nodes whose operations, fields and grids are already bound. Nodes hand each other batch::EvaluatedChunks as ordinary Rust values, so no row batch is materialised between them. metrics names each node after its position in that tree.

Three properties keep this apart from recognising a query shape in a finished physical plan:

  • Legality is a type and data-dependency question (plan::NativeNode::validate), so a new combination of supported operations is an ordinary tree, not another matcher.
  • A window binds its input and output grids separately, so a subquery’s inner grid is consumed as it is instead of being resampled onto the outer grid.
  • A series closes exactly once, on the chunk that says so, so a consumer can tell “nothing more here” from “no more input”.
