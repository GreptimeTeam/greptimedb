Module canonicalize 

Source
Expand description

Puts a canonical NativeExpr::Merge where a label rewrite or a metadata-label drop can give two series one label set.

A fused input hands over the series one scan partition holds. A node that writes an existing label or drops __name__/__type__/__unit__ can make two of them share a canonical label set (duplicates_canonical_labels); a consumer that reads whole label sets then needs a merge below it:

consumermerge below it?
the rootyes
Aggregate, ParameterizedAggregate, Vector, ParameterizedTopK, ParameterizedHistogram, ScalarOfyes
Binary, Set, Infoyes, on each evaluated-vector side (a scalar broadcast’s vector side included)
Windowyes
Map, ParameterizedMapyes, below it: a map can empty a point (histogram functions drop floats, math skips histograms), so a merge above it would judge occupancy the map already erased
Timestamp, Instant, VectorOfno

The NULL/'' key-column pair is not collected; see leaves_a_drop_to_the_storage_keys.

The pass is idempotent: a merge answers false to duplicates_canonical_labels, so it is safe to run at every segment boundary. Placement of the merge is the lowering’s decision.
