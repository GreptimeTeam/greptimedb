Module canonicalize

Puts a canonical merge where a label rewrite made one necessary.

A fused input hands over the pieces of a metric one scan partition holds, and a label rewrite in the tree can give two of those pieces one label set. Every consumer that answers a whole label set - a fold, a ranking, a vector match, the statement’s own output - then reads two series where Prometheus reads one, or answers the sum of a group twice. NativeExpr::Merge is the node that collects the pieces of one label set into one series, and this module decides where one is needed.

§What decides it

Only a rewrite can alias, and only one that writes a label its input already carries: duplicates_canonical_labels is that fact, derived from the tree and the tags each source reports. A tree with no such rewrite gains no merge at all, so a per-series query keeps every scan partition and pays nothing for this pass.

Where a merge is added is a property of the consumer, and of what the operations between the consumer and the rewrite do to one sample:

consumermerge below it?why
the rootyesthe answer names one series per label set, so two rows sharing one set are the error Prometheus reports
Aggregateyesa fold sums the values it is handed at a point, so two pieces of one series are summed as if the query said so twice
Vectoryesranking, presence checks and folds must read canonical series rather than duplicate fragments
Binary/Set over two vectorsyes, on both sideseach side is matched by label, and the kernel refuses two values of one field at a point only after the pair was matched
Infoyes, on both sidesit looks the info series up by identifying labels, so the pieces of one label set have to be one series first
Window over an evaluated vectoryesa window folds a range of one series, so it reads the series whole
Map, ParameterizedMapyes, below itpoint-wise, but not sample-preserving: the histogram functions drop float samples, math ignores native histograms, and a parameterized clamp can empty a point - and the label set a point’s occupancy is judged under is the rewritten one, so a merge above such a map would be handed the occupancy that is already gone
Timestamp, Instant, a scalar broadcastnoeach rewrites the value of a sample it read and keeps that sample’s position, so no occupancy is lost and the pieces are still told apart where the rewrite left them

A merge is never added below a raw scan, a scalar or aggregate state: it binds samples evaluated on a grid, and no consumer asks for one over those.

Canonicalizing a map’s input is what makes the histogram case work: in histogram_count(label_replace(x, "host", "same", "host", ".*")) two scan partitions each rewrite one series to {host="same"} and histogram_count drops both - they are float samples - before anything could report that the two now share a label set at one point. The merge is inserted between the rewrite and histogram_count, so the canonical router judges the occupancy the rewrite created and reports the collision instead of an empty answer.

Running the pass over its own output changes nothing: the node that gained a merge then answers one series per label set, so duplicates_canonical_labels is false for it and a second run finds nothing to add. That also makes the pass safe to apply at every segment boundary rather than only at the statement root.

What this pass does not decide is placement: whether the merge can be answered inside one execution is the lowering’s question. A merge that spans partitions uses a producer and the existing canonical router; downstream consumers read ordinary evaluated frames.
