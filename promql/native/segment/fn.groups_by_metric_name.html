pub fn groups_by_metric_name(node: &NativeNode) -> bool
Expand description

Whether a grouping in node keeps a label the existing planner’s column list cannot name.

An aggregate’s by(...) keeps the labels it lists that its input carries, and __name__ is one of them: the aggregate folds its groups by the metric name as by any other label. It is not a column of any scan, though - it is the name the raw frame carries - so the existing planner’s by(__name__) finds no such column and reports no label at all. A schema taken from that list would drop the metric name the native aggregate kept, and two groups differing only in their metric would come out as two rows under one label set, which is a series identity lost rather than an answer given.

without(...) needs no such check: both routes drop __name__ there. Nor does a tree with one source: a discovered selector’s source declares __name__ per metric, and a named one folds one metric whose name cannot merge two groups. What the check is for is the tree reading more than one source, where only a discovered source can report a name at all.
