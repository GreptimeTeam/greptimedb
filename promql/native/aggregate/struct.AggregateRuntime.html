Expand description

One aggregate node’s states, from the first chunk it is handed to the series it finishes with.

Fields§

§op: BoundAggregate

What the node computes, as the tree bound it: the kind it folds by and the stage it reports.

§schema: Arc<SeriesSchema>

The layout its input and output share: the fields every chunk has and the grid they are addressed on. A Complete aggregate neither adds nor drops a field, and it evaluates on its input’s grid, so one schema describes both sides.

§fold: Fold

What this node keeps between chunks, as the runtime’s own enum, so the chunk check can ask what the operation accepts.

§annotations: Option<PromqlAnnotationCollector>

The query’s annotation collector, once the driver installed it. Only an operation that skips histogram samples has anything to say, and it says it once.

§accumulator: Option<FloatAggregator>

The fold. None once Self::compute has taken it, which is also what says the node has nothing left to fold into.

§retained: Option<QuantileInput>

The whole input of a quantile aggregate. None for every other kind, and None once the kernel has answered from it.

§merger: Option<FloatMerger>§state_schema: Option<Arc<AggregateStateSchema>>§computed: bool

Whether the fold has been finished and its series handed over. A node computes once: a second pull finds the series it queued rather than a fold that ran again.

The driver reads this to decide whether the node settled: an aggregate answers only once its fold has run, so a child with nothing left to hand over is not an answer.

pub(crate) fn new( op: BoundAggregate, schema: Arc<SeriesSchema>, buffer: &mut NodeBuffer, ) -> Result<Self>

The states of a Complete aggregate over schema.

A stage other than Complete and a kind without a supported kernel are refused here, before a single chunk is folded: a node this runtime cannot compute must not start, because a partial answer would be one the caller never asked for. The rejection names what was found, so a reader can tell a tree this runtime cannot run from one it cannot run correctly.

Source

fn new_quantile( op: BoundAggregate, quantile: f64, schema: Arc<SeriesSchema>, buffer: &mut NodeBuffer, ) -> Result<Self>

The states of a Complete quantile aggregate over schema, whose φ is quantile.

A quantile is answered from its group’s whole sample set, so a stage that saw only part of a group would answer the quantile of a subset of it: the quantile of two partitions’ quantiles is not the quantile of their union, and there is no state to export or merge either. That is a property of the operation and not of this runtime, so what refuses a Partial or a Final one is the tree’s own check – aggregate_state_binding has no binding for a quantile, which crate::native::plan::NativeNode::validate reports, and crate::native::split declines a quantile for the same reason – and this starts the one stage that is left.

The same check is what puts the input on a grid: a Complete aggregate is validated to answer its input’s values on its input’s grid, and schema is the layout the node reports, so the grid the kernel reads its parameter on is there before this runs.

Source

pub(crate) fn pending(&self, chunk: &EvaluatedChunk) -> usize

What consuming chunk reserves while it is consumed.

A point-wise fold drops the chunk at the end of the call and keeps only its states, so the charge is the chunk’s own bytes – the figure evaluated_bytes reports, which is one pass over the chunk and no state between chunks – and not the operand_chunk_bytes figure a binary operand keeps, which exists because such an operand holds a series for the whole execution and so must count the slices of one buffer instead of the buffer once per chunk.

A quantile keeps the chunk instead, and what it holds is not the chunk alone: it is the allocations the chunk’s samples live in, billed once each, beside the chunk’s own descriptors (Self::retain_quantile, which is chunk_bytes_beside_samples plus unbilled_sample_buffers plus unbilled_tables). That figure is read from the chunk by the retainer itself, before it retains it, so nothing is held before it is reserved. Booking the chunk again here would reserve the same backing twice – once for the chunk being handed over and once for the allocations it points into – which is not a safer estimate but a refusal of an input whose own figure the pool admits.

pub(crate) fn accumulate( &mut self, chunk: EvaluatedChunk, buffer: &mut NodeBuffer, pending: usize, ) -> Result<()>

Folds one chunk into its group.

A chunk that closes its series closes nothing here: a group is not a series, so the last contribution of one member says nothing about the group. The fold keeps its states, which is what makes a group’s answer its whole group’s answer once the input ends.

A quantile keeps the chunk itself, for the same reason: the answer is the group’s sample set, so the samples have to survive until the input does.

Source

fn retain_quantile( &mut self, chunk: EvaluatedChunk, buffer: &mut NodeBuffer, ) -> Result<()>

Keeps one chunk of a quantile’s input until the input ends.

The chunk is kept whole rather than folded: the answer is the φ-quantile of the group’s sample set, and no fixed-width state holds a sample set. What it costs is measured the way a binary operand measures the chunks it retains, and for the same reason: what a quantile keeps is a series for the rest of the execution, so the allocation one buffer its chunks are slices of is counted once rather than once per chunk – and counted at all when the chunk holds a small slice of it, because the allocation is what stays resident. It is the chunk’s own descriptors (chunk_bytes_beside_samples) beside those allocations: the Arrow buffers its samples live in, once each (unbilled_sample_buffers), and the histogram tables they index into, once each (unbilled_tables). The figure is reserved before the push – the push is what makes the node hold it – and the reservation then settles on the whole input, which is what this node holds between chunks.

pub(crate) fn groups(&self) -> usize

The number of retained groups, for budgeting the output queue backing storage.

A point-wise fold knows its groups because it keyed them. A quantile has not grouped anything: the kernel does that when it answers. What it reports here is therefore the number of members it retained, which is an upper bound – every group has at least one member – and only ever sizes a reservation.

pub(crate) fn compute( &mut self, buffer: &mut NodeBuffer, queue_bytes: usize, ) -> Result<Option<AggregateOutput>>

Finishes the fold and returns one series per group, or None if the fold already ran.

None is what a node reports after it has queued its series: the caller reads them from the queue, exactly as it reads the chunks a binary node queued, so a second pull does not finish a fold whose states are gone.

Source

fn report_evidence(&mut self, evidence: HistogramEvidence)

Reports what the fold or merge recorded about its inputs, once, where the answer is final.

Only a Complete or a Final node reports: a Partial node hands its evidence on in the state it exports, because a point’s outcome is not decided until every partition has been merged and a message cannot be withdrawn once it has been collected. The collector is the node’s own handle, so its children keep theirs.

A poisoned point answers nothing, and the reconciliation its inputs needed is not reported for it: the summary already dropped that bit, which is what makes the message set the same whichever order the partitions arrived in.

Source

fn finish_quantile( &self, input: QuantileInput, buffer: &mut NodeBuffer, queue_bytes: usize, ) -> Result<Vec<Series>>

Answers a quantile from the input it kept, and hands the series over.

The parameter is the number the query wrote, so every point it covers carries it: the kernel reads q per point from an unlabelled single-field scalar on the aggregate’s own grid, and a point that scalar has no value at is a point with no result. That case cannot arise from a constant, but the kernel keeps the rule for the parameter it is written for.

The parameter covers the points the input holds and not the window they sit in: the kernel reads q only where a member has a sample, so a sparse input’s parameter is as wide as its rows. A parameter over the envelope would instead allocate every position between two far-apart points – a span sized by the statement’s range rather than by the data it reads, which the pool never admitted. The parameter is booked from the bound its rows give before it exists, and settles on its exact figure once it is built.

The reservation covers what is held while the kernel runs – the input, that parameter, and the kernel’s workspace – and then settles on the series the kernel answered, exactly as a point-wise fold’s finish does. The input is what stops being held when the kernel is done with it, so it is dropped before the settle rather than when this call returns: a settle read beside a live input would name a set that is never held, and the figure it left behind would be the one the next node’s admission had to fit into.
