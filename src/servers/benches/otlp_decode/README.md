# OTLP metrics decode experiment

This experiment uses uncompressed protobuf requests generated by
`metrics-bench-suite/bin/sample_loader` with `configs/samples_1750`,
`--protocol otlp`, `--replica 0`, and `--max-samples 1000`.
Save HTTP request bodies as `.pb` files, then run:

```sh
OTLP_DECODE_CORPUS=/path/to/corpus \
OTLP_DECODE_CAPACITY_REPORT=/path/to/capacity.txt \
cargo bench -p servers --bench bench_otlp_decode
```

The harness checks decoded-message equality before timing. Each iteration
decodes and drops the entire corpus; it does not append successive requests
into an uncleared message. Throughput is input protobuf bytes, not database
ingestion throughput. The capacity report measures attribute-vector backing
storage, excluding strings and the rest of the message; it is not process RSS.

## Candidates

- **bytes:** current prost decoder over `Bytes`.
- **slice:** prost decoder over `&[u8]`.
- **capacity_hint:** bounded preallocation of scalar data-point attributes.
  This follows the enterprise Remote Write decoder's focus on reducing
  repeated-container allocations. It still delegates wire validation,
  recursion handling and unknown fields to prost. It is benchmark-only.

## Local results (2026-09-10)

Release-mode isolated harness, the actual pinned `otel-arrow-rust` message
types, prost/prost-build 0.14.1, bytes 1.11.1; 12 suite requests, each containing
1,000 input samples. The isolated harness builds only benchmark dependencies,
not a release database binary. Criterion: 50 samples, 2 seconds warm-up,
5 seconds measurement for the real corpus.

| Decoder | Corpus time, final run | Throughput |
| --- | ---: | ---: |
| bytes | 17.568 ms | 334.79 MiB/s |
| slice | 18.596 ms | 316.30 MiB/s |
| capacity hint (32) | 17.437 ms | 337.32 MiB/s |

An earlier repeat measured 17.637 ms vs 17.327 ms for bytes vs capacity hint.
The observed improvement therefore ranged from approximately 0.7% to 1.8%.
A capacity hint of 16 measured 17.775 ms vs a 17.635 ms baseline.

The 32-entry hint increased aggregate attribute-vector capacity from
15,980,160 to 21,414,848 bytes (+34%). On a single empty scalar data point,
baseline decoding measured 87.130 ns vs 89.584 ns with the hint (+2.8%).

**Conclusion:** retain the current production decoder. The small, variable
improvement does not justify additional decoding wrappers and memory overhead.
Keep the candidate here so future alternatives can be compared with the same
corpus. These results do not establish an end-to-end ingestion speedup: the
standalone smoke test's default 3-second batching interval dominates latency.
