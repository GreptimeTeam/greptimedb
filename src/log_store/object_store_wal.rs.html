15//! Durable primitives of a WAL that stores entries as immutable object store
16//! objects.
17//!
18//! Entries of many regions are batched into a single object, written once and
19//! never mutated afterwards. An object is laid out as
20//!
21//! ```text
22//! header | segment (region 1) | ... | segment (region N) | footer | trailer
23//! ```
24//!
25//! The header carries the magic `GTWALOBJ`, the format version, the object
26//! sequence and the instance that wrote the object. Each segment holds the
27//! entries of exactly one region, ordered by entry id, and segments are ordered
28//! by region id. The footer indexes every segment with its region id, entry id
29//! range, byte range and CRC32. The fixed-size trailer points at the footer and
30//! carries the CRC32 of the footer and of the whole object, so a reader locates
31//! the footer by reading the fixed-length trailer at the end of the object.
32//!
33//! Object sequences increase monotonically within one prefix and may leave
34//! gaps, so recovery continues after the largest sequence it indexed. An object
35//! is created conditionally: rewriting a sequence with the content it already
36//! holds is a no-op at the object store, while different content under a taken
37//! sequence is a conflict. Recovery lists the objects, reads and verifies only
38//! the header, trailer and footer of each, and indexes the footers in sequence
39//! order to rebuild the object catalog, which rejects a sequence it already
40//! holds. Segments are read and checksummed only when a read decodes them.
41//!
42//! Entry ids are object-sequence-major, see [`entry_id`]: the high bits of an
43//! id name the object that holds the entry, the low bits its position among
44//! the entries of its region in that object.
