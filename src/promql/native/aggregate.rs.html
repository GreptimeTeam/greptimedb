15//! The run-time state of an aggregate node.
16//!
17//! An aggregate folds a whole vector into one series per group, so its node is the one that cannot
18//! answer as its input arrives: a group's value at a grid point is the fold of every value every
19//! member of the group has there, and the last member to arrive is the one that decides it. What the
20//! node keeps between chunks is therefore the fold's states and nothing else -- a chunk is folded as
21//! it arrives and dropped -- and it produces once, when the input ends.
22//!
23//! That is also why this runtime cannot tell an incomplete group from a complete one: it folds what
24//! it is handed. A [`AggregateStage::Complete`] aggregate is correct only if every contribution to
25//! each group lies within the streams this execution reads, which is the physical plan's job -- the
26//! caller that schedules scans and exchanges guarantees it, and a plan that ran a `Complete`
27//! aggregate once per partition and then combined the answers would be combining values that were
28//! each missing the other partitions' contributions. The stages that exist for that shape are
29//! [`AggregateStage::Partial`] and [`AggregateStage::Final`], which carry kernel accumulator
30//! state between executions.
31//!
32//! `quantile` is the one aggregate here that is not a fold of each point's values. Its answer is the
33//! φ-quantile of the group's whole sample set at that point, so there is no fixed-width accumulator
34//! that answers it, and no state that combines two partitions' quantiles into the quantile of their
35//! union. What the node keeps instead is its input: every series it was handed, until the input
36//! ends, when [`crate::aggregate::aggregate_quantile`] answers from all of it at once. That is also
37//! why `quantile` exists only as [`AggregateStage::Complete`] here, and why a plan that would have
38//! to fold it per partition has to keep the previous route instead of splitting it.
39//!
40//! There is no spill either: a `quantile` keeps the whole input of every group, at once, until the
41//! last chunk arrives, so what it holds is not bounded by the number of groups the way a fixed-width
42//! accumulator's is -- it is bounded by the pool. Each chunk is admitted before it is kept and the
43//! reservation settles on the input retained so far ([`AggregateRuntime::accumulate`]), so a
44//! statement whose groups' samples do not fit the pool is refused rather than served from disk, and
45//! a caller that needs an answer in bounded memory needs a wider pool rather than a wider node.
46//! Everything else in this runtime trades memory for the width of a point: a fold's state per group
47//! and point, this one's whole input.

81/// What a `Complete` aggregate keeps while its input arrives.
82///
83/// The eight point-wise aggregates fold each grid point's values into fixed-width state; `quantile`
84/// keeps the samples themselves, because the φ-quantile of a group is not a value its members' values
85/// fold to.
86#[derive(Clone, Copy)]
87enum Fold {
88    /// One fixed-width accumulator per point and field.
89    Pointwise(AggregateOp),
90    /// The whole input, kept until it ends.
91    Quantile,
92}
93
94/// The input a `quantile` aggregate keeps, until it has all of it.
95///
96/// The members are the series the node was handed, in the order they arrived: that order is the order
97/// [`aggregate_quantile`] folds a group's members in, and a series delivered in several chunks
98/// contributes at each position it holds, so the pieces of one series answer what the whole series
99/// would have. Nothing here is grouped: the kernel groups, and it groups the same way for a chunk as
100/// for a series of its own.
101struct QuantileInput {
102    /// The φ the query wrote. The kernel reads it as Prometheus does, so a value outside `[0, 1]`
103    /// answers `-Infinity` or `+Infinity` rather than being refused here.
104    quantile: f64,
105    /// One entry per series this node was handed.
106    series: Vec<Series>,
107    /// The histogram tables the retained chunks index into, by the address of the allocation behind
108    /// their `Arc`.
109    ///
110    /// A table is one allocation however many chunks of a series index into it, so it is billed once
111    /// -- by the first chunk that references it -- exactly as a binary operand bills the tables of
112    /// the chunks it retains. That is what keeps a series delivered in a thousand chunks from costing
113    /// a thousand tables, and what keeps a table from costing nothing: the per-chunk figure leaves
114    /// its tables out ([`chunk_bytes_beside_samples`]), so a table in neither this set nor a
115    /// reservation is a table nothing covers.
116    tables: HashSet<usize>,
117    /// The Arrow allocations the retained chunks' samples live in, by the address of the allocation
118    /// behind their `Buffer`.
119    ///
120    /// The chunks of one Arrow batch are the same story as its tables one level down, and the same
121    /// answer: what a retainer keeps is the allocation its slices point into, and one allocation is
122    /// one however many chunks slice it, so it is billed once -- by the first chunk that references
123    /// it ([`unbilled_sample_buffers`]) -- rather than once per chunk. That is what keeps a series
124    /// handed over as a thousand slices of one buffer from costing that buffer a thousand times. A
125    /// chunk that holds a small slice of a large allocation is charged the allocation, because the
126    /// allocation is what stays resident; its rows would be the smaller and wrong figure.
127    buffers: HashSet<usize>,
128    /// The bytes the retained chunks hold, folded in as they arrive.
129    ///
130    /// Each chunk is measured once, by what it holds on its own ([`chunk_bytes_beside_samples`]):
131    /// its axis, its descriptors and its labels, beside the allocations it is the first to reference
132    /// -- the Arrow buffers its samples live in and the histogram tables they index into, each
133    /// billed once as [`unbilled_sample_buffers`] and [`unbilled_tables`] report them. Neither the
134    /// allocation those samples are slices of nor the struct that carries the chunk is part of the
135    /// figure: the first is billed as the allocation it is and not as the rows a chunk holds of it,
136    /// and the second is the slot the vector holds the chunk in. [`Self::bytes`] adds that vector
137    /// from the capacity it holds, which is why the struct is not counted here as well.
138    held: usize,
139}
140
141impl QuantileInput {
142    /// The bytes this input holds: the chunks it retained and the vector that carries them.
143    ///
144    /// The retained figure is [`Self::held`], which is folded in chunk by chunk, and the vector is
145    /// counted by the capacity it really holds -- the capacity `retain_quantile` reserved before it
146    /// grew -- so this is what the node has to reserve rather than a second estimate of it.
147    ///
148    /// The two do not overlap. A chunk's `Series` is carried inside one slot of that vector, so
149    /// `held` counts what the chunk holds beside the struct ([`chunk_bytes_beside_samples`]) and the
150    /// capacity here counts every slot the vector owns, occupied or not. Counting the struct in both
151    /// would charge each occupied slot twice; counting it in neither would leave every slot the
152    /// vector holds uncovered.
153    fn bytes(&self) -> usize {
154        std::mem::size_of::<Self>()
155            .saturating_add(
156                self.series
157                    .capacity()
158                    .saturating_mul(std::mem::size_of::<Series>()),
159            )
160            .saturating_add(self.held)
161    }
162}

164/// One aggregate node's states, from the first chunk it is handed to the series it finishes with.
165pub(crate) struct AggregateRuntime {
166    /// What the node computes, as the tree bound it: the kind it folds by and the stage it reports.
167    op: BoundAggregate,
168    /// The layout its input and output share: the fields every chunk has and the grid they are
169    /// addressed on. A `Complete` aggregate neither adds nor drops a field, and it evaluates on its
170    /// input's grid, so one schema describes both sides.
171    schema: Arc<SeriesSchema>,
172    /// What this node keeps between chunks, as the runtime's own enum, so the chunk check can ask
173    /// what the operation accepts.
174    fold: Fold,
175    /// The query's annotation collector, once the driver installed it. Only an operation that skips
176    /// histogram samples has anything to say, and it says it once.
177    annotations: Option<PromqlAnnotationCollector>,
178    /// The fold. `None` once [`Self::compute`] has taken it, which is also what says the node has
179    /// nothing left to fold into.
180    accumulator: Option<FloatAggregator>,
181    /// The whole input of a `quantile` aggregate. `None` for every other kind, and `None` once the
182    /// kernel has answered from it.
183    retained: Option<QuantileInput>,
184    merger: Option<FloatMerger>,
185    state_schema: Option<Arc<AggregateStateSchema>>,
186    /// Whether the fold has been finished and its series handed over. A node computes once: a second
187    /// pull finds the series it queued rather than a fold that ran again.
188    ///
189    /// The driver reads this to decide whether the node settled: an aggregate answers only once its
190    /// fold has run, so a child with nothing left to hand over is not an answer.
191    pub(crate) computed: bool,
192}

194impl AggregateRuntime {
195    /// The PromQL name of the aggregate this node folds, as an annotation names it.
196    fn aggregate_name(&self) -> &'static str {
197        match self.fold {
198            Fold::Pointwise(AggregateOp::Sum) => "sum",
199            Fold::Pointwise(AggregateOp::Count) => "count",
200            Fold::Pointwise(AggregateOp::Avg) => "avg",
201            Fold::Pointwise(AggregateOp::Min) => "min",
202            Fold::Pointwise(AggregateOp::Max) => "max",
203            Fold::Pointwise(AggregateOp::Group) => "group",
204            Fold::Pointwise(AggregateOp::Stddev) => "stddev",
205            Fold::Pointwise(AggregateOp::Stdvar) => "stdvar",
206            Fold::Quantile => "quantile",
207        }
208    }

212        self.annotations = Some(collector);

215    /// What this node computes, for a rejection that has to say what it refused.
216    ///
217    /// It names the kind this node computes, which distinguishes it from another node in the tree.
218    fn describe(&self) -> String {
219        format!("{:?}", self.op.kind)
220    }

222    /// The states of a `Complete` aggregate over `schema`.
223    ///
224    /// A stage other than `Complete` and a kind without a supported kernel are refused here, before a single
225    /// chunk is folded: a node this runtime cannot compute must not start, because a partial answer
226    /// would be one the caller never asked for. The rejection names what was found, so a reader can
227    /// tell a tree this runtime cannot run from one it cannot run correctly.
228    pub(crate) fn new(
229        op: BoundAggregate,
230        schema: Arc<SeriesSchema>,
231        buffer: &mut NodeBuffer,
232    ) -> Result<Self> {
233        let kind = match op.kind {
234            AggregateKind::Sum => AggregateOp::Sum,
235            AggregateKind::Count => AggregateOp::Count,
236            AggregateKind::Avg => AggregateOp::Avg,
237            AggregateKind::Min => AggregateOp::Min,
238            AggregateKind::Max => AggregateOp::Max,
239            AggregateKind::Group => AggregateOp::Group,
240            AggregateKind::Stddev => AggregateOp::Stddev,
241            AggregateKind::Stdvar => AggregateOp::Stdvar,
242            // The one kind with no accumulator: it keeps its input instead, which is a state of its
243            // own and is built by [`Self::new_quantile`]. The φ is the only parameter an aggregate
244            // carries, and the arm that names the kind is the one place it is read.
245            AggregateKind::Quantile { quantile } => {
246                return Self::new_quantile(op, quantile, schema, buffer);
247            }
248        };
249        let (state_kind, state_components) = aggregate_state_binding(op.kind, op.field_kind)
250            .ok_or_else(|| {
251                DataFusionError::NotImplemented("aggregate kind has no mergeable state".into())
252            })?;
253        let state_schema = schema.eval_grid.as_ref().map(|grid| {
254            Arc::new(AggregateStateSchema {
255                group: op.group.clone(),
256                kind: state_kind,
257                components: state_components.into(),
258                accumulators: schema.fields.clone(),
259                grid: grid.clone(),
260            })
261        });
262        if op.stage == AggregateStage::Final {
263            let merger = FloatMerger::try_new(&schema, kind)?;
264            buffer.resize(merger.state_bytes())?;
265            return Ok(Self {
266                op,
267                fold: Fold::Pointwise(kind),
268                annotations: None,
269                schema,
270                accumulator: None,
271                retained: None,
272                merger: Some(merger),
273                state_schema,
274                computed: false,
275            });
276        }
277        let name_count = match &op.group {
278            BoundGrouping::By(labels) | BoundGrouping::Without(labels) => labels.len(),
279        };
280        let name_bytes = name_count.saturating_mul(std::mem::size_of::<&str>());
281        buffer.grow(name_bytes)?;
282        let names: Vec<&str> = match &op.group {
283            BoundGrouping::By(labels) | BoundGrouping::Without(labels) => {
284                labels.iter().map(|label| label.as_ref()).collect()
285            }
286        };
287        let grouping = match &op.group {
288            BoundGrouping::By(_) => Grouping::By(&names),
289            BoundGrouping::Without(_) => Grouping::Without(&names),
290        };
291        let name_bytes = names.len().saturating_mul(std::mem::size_of::<&str>());
292        let initial = FloatAggregator::try_new_budgeted(&schema, kind, grouping, |bytes| {
293            buffer.resize(bytes.saturating_add(name_bytes))
294        })?;
295        drop(names);
296        buffer.resize(initial.state_bytes())?;
297        Ok(Self {
298            op,
299            fold: Fold::Pointwise(kind),
300            annotations: None,
301            schema,
302            accumulator: Some(initial),
303            retained: None,
304            merger: None,
305            state_schema,
306            computed: false,
307        })
308    }

310    /// The states of a `Complete` `quantile` aggregate over `schema`, whose φ is `quantile`.
311    ///
312    /// A `quantile` is answered from its group's whole sample set, so a stage that saw only part of
313    /// a group would answer the quantile of a subset of it: the quantile of two partitions'
314    /// quantiles is not the quantile of their union, and there is no state to export or merge
315    /// either. That is a property of the operation and not of this runtime, so what refuses a
316    /// `Partial` or a `Final` one is the tree's own check -- [`aggregate_state_binding`] has no
317    /// binding for a `quantile`, which [`crate::native::plan::NativeNode::validate`] reports, and
318    /// [`crate::native::split`] declines a `quantile` for the same reason -- and this starts the one
319    /// stage that is left.
320    ///
321    /// The same check is what puts the input on a grid: a `Complete` aggregate is validated to
322    /// answer its input's values on its input's grid, and `schema` is the layout the node reports,
323    /// so the grid the kernel reads its parameter on is there before this runs.
324    fn new_quantile(
325        op: BoundAggregate,
326        quantile: f64,
327        schema: Arc<SeriesSchema>,
328        buffer: &mut NodeBuffer,
329    ) -> Result<Self> {
330        let retained = QuantileInput {
331            quantile,
332            series: Vec::new(),
333            tables: HashSet::new(),
334            buffers: HashSet::new(),
335            held: 0,
336        };
337        buffer.resize(retained.bytes())?;
338        Ok(Self {
339            op,
340            fold: Fold::Quantile,
341            annotations: None,
342            schema,
343            accumulator: None,
344            retained: Some(retained),
345            merger: None,
346            state_schema: None,
347            computed: false,
348        })
349    }

351    /// What consuming `chunk` reserves while it is consumed.
352    ///
353    /// A point-wise fold drops the chunk at the end of the call and keeps only its states, so the
354    /// charge is the chunk's own bytes -- the figure [`evaluated_bytes`] reports, which is one pass
355    /// over the chunk and no state between chunks -- and not the `operand_chunk_bytes` figure a
356    /// binary operand keeps, which exists because such an operand holds a series for the whole
357    /// execution and so must count the slices of one buffer instead of the buffer once per chunk.
358    ///
359    /// A `quantile` keeps the chunk instead, and what it holds is not the chunk alone: it is the
360    /// allocations the chunk's samples live in, billed once each, beside the chunk's own descriptors
361    /// ([`Self::retain_quantile`], which is [`chunk_bytes_beside_samples`] plus
362    /// [`unbilled_sample_buffers`] plus [`unbilled_tables`]). That figure is read from the chunk by
363    /// the retainer itself, before it retains it, so nothing is held before it is reserved. Booking
364    /// the chunk again here would reserve the same backing twice -- once for the chunk being handed
365    /// over and once for the allocations it points into -- which is not a safer estimate but a
366    /// refusal of an input whose own figure the pool admits.
367    pub(crate) fn pending(&self, chunk: &EvaluatedChunk) -> usize {
368        match self.fold {
369            Fold::Pointwise(_) => evaluated_bytes(chunk),
370            Fold::Quantile => 0,
371        }
372    }

374    /// Folds one chunk into its group.
375    ///
376    /// A chunk that closes its series closes nothing here: a group is not a series, so the last
377    /// contribution of one member says nothing about the group. The fold keeps its states, which is
378    /// what makes a group's answer its whole group's answer once the input ends.
379    ///
380    /// A `quantile` keeps the chunk itself, for the same reason: the answer is the group's sample set,
381    /// so the samples have to survive until the input does.
382    pub(crate) fn accumulate(
383        &mut self,
384        chunk: EvaluatedChunk,
385        buffer: &mut NodeBuffer,
386        pending: usize,
387    ) -> Result<()> {
388        let Fold::Pointwise(kind) = self.fold else {
389            return self.retain_quantile(chunk, buffer);
390        };
391        // `Series` keeps its fields public, so a chunk can be built by struct literal against
392        // another schema; the states are indexed by absolute position on this node's grid, so a
393        // chunk of another field count or another grid would be folded into the wrong places.
394        validate_aggregate_series(&self.schema, &chunk.series, kind)
395            .map_err(|error| folded_chunk(&self.describe(), error))?;
396        if histogram_samples(kind) == HistogramSamples::Ignored
397            && !crate::map::is_float_series(&chunk.series)
398            && let Some(collector) = &self.annotations
399        {
400            // Prometheus reports once that it skipped samples it cannot order or average over; the
401            // fold keeps going on the float samples it can read.
402            collector.record_info(format!(
403                "{}: ignored native histogram samples",
404                self.aggregate_name()
405            ));
406            // The collector keeps the message, so the node has said its piece.
407            self.annotations = None;
408        }
409        let Some(accumulator) = self.accumulator.as_mut() else {
410            return Err(no_fold(&self.describe()));
411        };
412        // Keep the chunk covered while the fold decides whether it needs a new group or block.
413        accumulator.update_budgeted(&chunk.series, |fold_bytes| {
414            buffer.resize(pending.saturating_add(fold_bytes))
415        })?;
416        drop(chunk);
417        buffer.resize(accumulator.state_bytes())
418    }
419
420    /// Keeps one chunk of a `quantile`'s input until the input ends.
421    ///
422    /// The chunk is kept whole rather than folded: the answer is the φ-quantile of the group's sample
423    /// set, and no fixed-width state holds a sample set. What it costs is measured the way a binary
424    /// operand measures the chunks it retains, and for the same reason: what a `quantile` keeps is a
425    /// series for the rest of the execution, so the allocation one buffer its chunks are slices of is
426    /// counted once rather than once per chunk -- and counted at all when the chunk holds a small
427    /// slice of it, because the allocation is what stays resident. It is the chunk's own descriptors
428    /// ([`chunk_bytes_beside_samples`]) beside those allocations: the Arrow buffers its samples live
429    /// in, once each ([`unbilled_sample_buffers`]), and the histogram tables they index into, once
430    /// each ([`unbilled_tables`]). The figure is reserved before the push -- the push is what makes
431    /// the node hold it -- and the reservation then settles on the whole input, which is what this
432    /// node holds between chunks.
433    fn retain_quantile(&mut self, chunk: EvaluatedChunk, buffer: &mut NodeBuffer) -> Result<()> {
434        // A quantile reads float values and skips a histogram sample, so a chunk only has to fit the
435        // schema and the grid -- exactly what the kernel's own input check asks for.
436        validate_grid_series(&self.schema, &chunk.series)
437            .map_err(|error| folded_chunk(&self.describe(), error))?;
438        if !crate::map::is_float_series(&chunk.series)
439            && let Some(collector) = &self.annotations
440        {
441            // Prometheus reports once that it skipped samples it cannot order; the kernel folds the
442            // float samples it can read.
443            collector.record_info(format!(
444                "{}: ignored native histogram samples",
445                self.aggregate_name()
446            ));
447            self.annotations = None;
448        }
449        let Some(retained) = self.retained.as_mut() else {
450            return Err(no_fold(&self.describe()));
451        };
452        // What this chunk adds to what the node holds: the allocations its samples live in and the
453        // histogram tables it is the first chunk to reference -- each billed once, because one
454        // allocation is one however many chunks slice it -- plus the descriptors the chunk keeps.
455        let (buffers, buffer_bytes) = unbilled_sample_buffers(&chunk.series, &retained.buffers);
456        let (tables, table_bytes) = unbilled_tables(&chunk.series, &retained.tables);
457        let bytes = chunk_bytes_beside_samples(&chunk.series)
458            .saturating_add(buffer_bytes)
459            .saturating_add(table_bytes);
460        buffer.grow(bytes)?;
461        // The slot the chunk is about to take, and - when the vector has to grow for it - the
462        // capacity it grows to. `Vec::push` doubles, so booking one slot would let the real
463        // allocation outrun what the pool admitted; the target is booked instead, and the settle
464        // below then reads back the exact capacity the vector holds. The vector's slots are not part
465        // of `held`: [`QuantileInput::bytes`] counts them from that capacity, so booking them here
466        // and folding them there would charge them twice.
467        let needed = retained.series.len().saturating_add(1);
468        if needed > retained.series.capacity() {
469            let target = retained.series.capacity().saturating_mul(2).max(needed);
470            buffer.grow(
471                target
472                    .saturating_sub(retained.series.capacity())
473                    .saturating_mul(std::mem::size_of::<Series>()),
474            )?;
475            retained
476                .series
477                .try_reserve_exact(target.saturating_sub(retained.series.len()))
478                .map_err(|error| {
479                    DataFusionError::Execution(format!(
480                        "cannot retain the `quantile` input: {error}"
481                    ))
482                })?;
483        }
484        retained.series.push(chunk.series);
485        // From here the node keeps those tables and allocations alive itself, so a chunk arriving
486        // later that references one is charged its own descriptors and not the allocation again.
487        retained.tables.extend(tables);
488        retained.buffers.extend(buffers);
489        retained.held = retained.held.saturating_add(bytes);
490        buffer.resize(retained.bytes())
491    }

493    /// Merges one state chunk into this final aggregate.
494    pub(crate) fn accumulate_state(
495        &mut self,
496        chunk: StateChunk,
497        buffer: &mut NodeBuffer,
498        pending: usize,
499    ) -> Result<()> {
500        let expected = self.state_schema.as_ref().ok_or_else(|| {
501            DataFusionError::NotImplemented("this runtime does not merge aggregate state".into())
502        })?;
503        let StateChunk::Row(row) = chunk else {
504            return Err(DataFusionError::Internal(
505                "Final aggregate received producer state series".into(),
506            ));
507        };
508        if row.fields.kind() != expected.kind
509            || row.fields.components() != expected.components.as_ref()
510        {
511            return Err(DataFusionError::NotImplemented(
512                "this runtime does not merge that kind of state".into(),
513            ));
514        }
515        if row
516            .time
517            .grid()
518            .is_none_or(|grid| grid.spec() != expected.grid.spec())
519        {
520            return Err(DataFusionError::Execution(
521                "aggregate state grid mismatch".into(),
522            ));
523        }
524        if row.fields.len() != self.schema.fields.len() {
525            return Err(DataFusionError::Execution(
526                "aggregate state field count mismatch".into(),
527            ));
528        }
529        let description = self.describe();
530        let merger = self.merger.as_mut().ok_or_else(|| no_fold(&description))?;
531        merger.merge_row(&row, |bytes| buffer.resize(pending.saturating_add(bytes)))?;
532        drop(row);
533        buffer.resize(merger.state_bytes())
534    }

536    /// Transient bytes required to consume a state chunk.
537    pub(crate) fn pending_state(&self, chunk: &StateChunk) -> usize {
538        match chunk {
539            StateChunk::Series { .. } => state_bytes(chunk),
540            StateChunk::Row(row) => crate::native::state::state_row_bytes(row),
541        }
542    }

544    /// The number of retained groups, for budgeting the output queue backing storage.
545    ///
546    /// A point-wise fold knows its groups because it keyed them. A `quantile` has not grouped
547    /// anything: the kernel does that when it answers. What it reports here is therefore the number
548    /// of members it retained, which is an upper bound -- every group has at least one member -- and
549    /// only ever sizes a reservation.
550    pub(crate) fn groups(&self) -> usize {
551        if let Some(input) = self.retained.as_ref() {
552            return input.series.len();
553        }
554        self.accumulator.as_ref().map_or(0, FloatAggregator::groups)
555    }
556
557    /// Finishes the fold and returns one series per group, or `None` if the fold already ran.
558    ///
559    /// `None` is what a node reports after it has queued its series: the caller reads them from the
560    /// queue, exactly as it reads the chunks a binary node queued, so a second pull does not finish
561    /// a fold whose states are gone.
562    pub(crate) fn compute(
563        &mut self,
564        buffer: &mut NodeBuffer,
565        queue_bytes: usize,
566    ) -> Result<Option<AggregateOutput>> {
567        if self.computed {
568            return Ok(None);
569        }
570        self.computed = true;
571        if let Some(input) = self.retained.take() {
572            let output = self.finish_quantile(input, buffer, queue_bytes)?;
573            return Ok(Some(AggregateOutput::Samples(output)));
574        }
575        if let Some(accumulator) = self.accumulator.take() {
576            return match self.op.stage {
577                AggregateStage::Complete => {
578                    // What the fold recorded about its inputs is reported here, where this node's
579                    // answer is the whole answer.
580                    let evidence = accumulator.evidence_summary();
581                    let output = accumulator.finish_budgeted(|total| {
582                        buffer.resize(total.saturating_add(queue_bytes))
583                    })?;
584                    let output_vec_bytes = output
585                        .capacity()
586                        .saturating_mul(std::mem::size_of::<Series>());
587                    charge_samples(buffer, &output, output_vec_bytes, queue_bytes)?;
588                    self.report_evidence(evidence);
589                    Ok(Some(AggregateOutput::Samples(output)))
590                }
591                AggregateStage::Partial => {
592                    let state_schema = self
593                        .state_schema
594                        .clone()
595                        .ok_or_else(|| no_fold(&self.describe()))?;
596                    // The fold builds the chunk's own representation, so handing it over costs no
597                    // second copy and no second charge: what was admitted for the groups is what
598                    // the chunk now holds.
599                    //
600                    // What the fold recorded travels in that state instead of being reported here:
601                    // one partition's evidence is a claim about a point the merge has not decided
602                    // yet, and a message cannot be taken back.
603                    let partial = accumulator
604                        .finish_partial_budgeted(|bytes| buffer.resize(bytes + queue_bytes))?;
605                    let chunk = state_chunk_from_partial(partial, state_schema, &self.op)?;
606                    Ok(Some(AggregateOutput::State(chunk)))
607                }
608                AggregateStage::Final => Err(no_fold(&self.describe())),
609            };
610        }
611        if let Some(merger) = self.merger.take() {
612            // The merge saw every partition's state, so this node is where the point's outcome is
613            // final and where its evidence is reported.
614            let evidence = merger.evidence_summary();
615            let output =
616                merger.finish_budgeted(|total| buffer.resize(total.saturating_add(queue_bytes)))?;
617            let output_vec_bytes = output
618                .capacity()
619                .saturating_mul(std::mem::size_of::<Series>());
620            charge_samples(buffer, &output, output_vec_bytes, queue_bytes)?;
621            self.report_evidence(evidence);
622            return Ok(Some(AggregateOutput::Samples(output)));
623        }
624        Err(no_fold(&self.describe()))
625    }
626
627    /// Reports what the fold or merge recorded about its inputs, once, where the answer is final.
628    ///
629    /// Only a `Complete` or a `Final` node reports: a `Partial` node hands its evidence on in the
630    /// state it exports, because a point's outcome is not decided until every partition has been
631    /// merged and a message cannot be withdrawn once it has been collected. The collector is the
632    /// node's own handle, so its children keep theirs.
633    ///
634    /// A poisoned point answers nothing, and the reconciliation its inputs needed is not reported
635    /// for it: the summary already dropped that bit, which is what makes the message set the same
636    /// whichever order the partitions arrived in.
637    fn report_evidence(&mut self, evidence: HistogramEvidence) {
638        if self.op.stage == AggregateStage::Partial {
639            return;
640        }
641        let Some(collector) = self.annotations.take() else {
642            return;
643        };
644        let name = self.aggregate_name();
645        if evidence.incompatible_layout {
646            collector.record_warning(format!(
647                "{name}: incompatible native histogram layouts, the result is removed"
648            ));
649        }
650        if evidence.custom_bounds_reconciled {
651            collector.record_info(format!("{name}: custom buckets reconciled"));
652        }
653        if evidence.counter_reset_collision {
654            collector.record_warning(format!("{name}: contradictory reset hints"));
655        }
656    }
657    /// Answers a `quantile` from the input it kept, and hands the series over.
658    ///
659    /// The parameter is the number the query wrote, so every point it covers carries it: the kernel
660    /// reads `q` per point from an unlabelled single-field scalar on the aggregate's own grid, and a
661    /// point that scalar has no value at is a point with no result. That case cannot arise from a
662    /// constant, but the kernel keeps the rule for the parameter it is written for.
663    ///
664    /// The parameter covers the points the input holds and not the window they sit in: the kernel
665    /// reads `q` only where a member has a sample, so a sparse input's parameter is as wide as its
666    /// rows. A parameter over the envelope would instead allocate every position between two
667    /// far-apart points -- a span sized by the statement's range rather than by the data it reads,
668    /// which the pool never admitted. The parameter is booked from the bound its rows give before it
669    /// exists, and settles on its exact figure once it is built.
670    ///
671    /// The reservation covers what is held while the kernel runs -- the input, that parameter, and
672    /// the kernel's workspace -- and then settles on the series the kernel answered, exactly as a
673    /// point-wise fold's finish does. The input is what stops being held when the kernel is done with
674    /// it, so it is dropped before the settle rather than when this call returns: a settle read
675    /// beside a live input would name a set that is never held, and the figure it left behind would
676    /// be the one the next node's admission had to fit into.
677    fn finish_quantile(
678        &self,
679        input: QuantileInput,
680        buffer: &mut NodeBuffer,
681        queue_bytes: usize,
682    ) -> Result<Vec<Series>> {
683        let grid = self.schema.eval_grid.clone().ok_or_else(|| {
684            DataFusionError::Execution(
685                "a `quantile` aggregate needs an evaluated grid to read its parameter on".into(),
686            )
687        })?;
688        let workspace = quantile_workspace_bytes(&self.schema, &input);
689        // Admitted before the parameter exists, because building it is what makes this node hold
690        // it: the bound is what a parameter over the input's points can take, and the resize below
691        // settles on what it did take.
692        buffer.resize(
693            input
694                .bytes()
695                .saturating_add(quantile_parameter_bound_bytes(&input))
696                .saturating_add(workspace)
697                .saturating_add(queue_bytes),
698        )?;
699        let positions = quantile_positions(&input);
700        let parameter = quantile_parameter(&grid, input.quantile, &positions)?;
701        // The collected positions are what the bound above covered and what this node no longer
702        // holds, so they go before the figure settles.
703        drop(positions);
704        let held = input
705            .bytes()
706            .saturating_add(series_bytes(&parameter))
707            .saturating_add(workspace);
708        buffer.resize(held.saturating_add(queue_bytes))?;
709        let names: Vec<&str> = match &self.op.group {
710            BoundGrouping::By(labels) | BoundGrouping::Without(labels) => {
711                labels.iter().map(|label| label.as_ref()).collect()
712            }
713        };
714        let grouping = match &self.op.group {
715            BoundGrouping::By(_) => Grouping::By(&names),
716            BoundGrouping::Without(_) => Grouping::Without(&names),
717        };
718        let output = aggregate_quantile(&self.schema, &input.series, &parameter, grouping)
719            .map_err(|error| folded_chunk(&self.describe(), error))?;
720        drop(names);
721        drop(parameter);
722        // The input is what this node held until the kernel answered, and it is given back before
723        // the reservation settles on the answer: the settle below is what the node holds from then
724        // on, so it must be read from the set that is really alive -- the answer and the queue --
725        // rather than from the answer beside an input this call only drops on its way out. The
726        // kernel's answer holds nothing of the input: the builder copies the samples it keeps.
727        drop(input);
728        let output_vec_bytes = output
729            .capacity()
730            .saturating_mul(std::mem::size_of::<Series>());
731        charge_samples(buffer, &output, output_vec_bytes, queue_bytes)?;
732        Ok(output)
733    }
734}

736/// The field the `quantile` parameter is bound under, which the kernel reads as its scalar.
737const QUANTILE_PARAMETER_FIELD: &str = "scalar";
738
739/// The points the retained input holds, once each, in ascending order.
740///
741/// A group's answer is decided at the points at least one of its members holds a sample at, and its
742/// members are drawn from the input, so these are every point the kernel can ask its parameter for.
743/// They are the positions the input's rows sit at -- not the window they span, which two far-apart
744/// points make as wide as the grid.
745fn quantile_positions(input: &QuantileInput) -> Vec<usize> {
746    union_positions(input.series.iter().map(|series| &series.time)).collect()
747}
748
749/// The parameter a `quantile` reads at each point: the φ the query wrote, unlabelled and single
750/// field, at `positions` and nowhere else.
751///
752/// The kernel reads `q` per point and treats a point it has no value at as a point with no result,
753/// so the parameter has to cover exactly the points that can be asked for and may omit every other
754/// one. [`GridSeriesBuilder`] is what makes that cheap: the axis keeps the runs of consecutive
755/// positions rather than a row per position, so two far-apart points cost two rows and two spans
756/// instead of every position between them.
757///
758/// An input holding no point has nothing to decide, which the kernel answers with no output: an
759/// empty scalar over the grid says the same thing and costs nothing.
760fn quantile_parameter(grid: &Arc<EvalGrid>, quantile: f64, positions: &[usize]) -> Result<Series> {
761    let schema = Arc::new(SeriesSchema {
762        fields: Arc::from([FieldSpec {
763            name: QUANTILE_PARAMETER_FIELD.into(),
764        }]),
765        eval_grid: Some(Arc::clone(grid)),
766    });
767    let metric = SeriesLabels::try_new(None, Vec::new())
768        .map_err(|error| DataFusionError::External(Box::new(error)))?;
769    let mut builder = GridSeriesBuilder::try_new(Arc::clone(&schema))?;
770    for position in positions {
771        builder.push(*position, &[Some(quantile)])?;
772    }
773    match builder.finish(metric)? {
774        Some(parameter) => Ok(parameter),
775        None => constant_series(
776            &schema,
777            GridRange::try_new(Arc::clone(grid), 0, 0)
778                .map_err(|error| DataFusionError::External(Box::new(error)))?,
779            quantile,
780        ),
781    }
782}

784/// The most a `quantile` parameter over `input` can cost, before it is built.
785///
786/// The parameter holds one value and one position per point it covers, and one span per run of
787/// them; a run is at least one point long, so the input's rows bound all of those. The figure is
788/// what the pool admits ahead of the allocation, and [`series_bytes`] is what it settles on once
789/// the parameter exists: what is admitted is what the parameter really takes, wherever its points
790/// sit on the grid.
791fn quantile_parameter_bound_bytes(input: &QuantileInput) -> usize {
792    let rows: usize = input.series.iter().map(|series| series.time.len()).sum();
793    let per_point = std::mem::size_of::<usize>() // its position, while the points are collected
794        .saturating_add(std::mem::size_of::<f64>()) // the value it carries
795        .saturating_add(2 * std::mem::size_of::<usize>()) // the span of a run of one point
796        .saturating_add(std::mem::size_of::<f64>()); // the array's validity slot for it
797    std::mem::size_of::<Series>()
798        .saturating_add(std::mem::size_of::<TimeAxis>())
799        .saturating_add(rows.saturating_mul(per_point))
800}
801
802/// The bytes the `quantile` kernel needs beside its retained input while it answers.
803///
804/// [`aggregate_quantile`] reports no workspace as it allocates, so this is an estimate reserved once
805/// before it runs, in the same spirit as the whole-vector kernels'. What it covers: the state it
806/// keeps per member (one position list, one heap entry and one cursor per field), its own copy of the
807/// parameter (one `(position, φ)` pair per point the parameter covers, which the input's rows bound
808/// because the parameter is only built over the points the input holds), the temporaries of one grid
809/// point (its members' values, the copy the kernel sorts, and one row of the width it folds), and the
810/// rows it builds -- the group being built and the groups it has already handed over. The row count is
811/// the input's own: a group's rows are the points at least one of its members holds a sample at, so
812/// the input's rows bound every group's rows and their sum.
813fn quantile_workspace_bytes(schema: &SeriesSchema, input: &QuantileInput) -> usize {
814    let width = schema.fields.len();
815    let members = input.series.len();
816    let rows: usize = input.series.iter().map(|series| series.time.len()).sum();
817    let per_member = std::mem::size_of::<(usize, usize, usize)>()
818        .saturating_add(std::mem::size_of::<usize>())
819        .saturating_add(width.saturating_mul(4 * std::mem::size_of::<usize>()));
820    let per_point = members
821        .saturating_mul(2 * std::mem::size_of::<f64>())
822        .saturating_add(width.saturating_mul(std::mem::size_of::<Option<f64>>()));
823    // One row, charged twice: the builder holds one group at a time and the series it has already
824    // handed over are held beside it.
825    let per_row = 2 * width
826        .saturating_mul(std::mem::size_of::<f64>())
827        .saturating_add(2 * std::mem::size_of::<usize>())
828        .saturating_add(1);
829    // The parameter copy, charged twice for the capacity a growing vector keeps over its length.
830    let parameter_copy = 2 * rows.saturating_mul(std::mem::size_of::<(usize, f64)>());
831    members
832        .saturating_mul(per_member)
833        .saturating_add(per_point)
834        .saturating_add(rows.saturating_mul(per_row))
835        .saturating_add(parameter_copy)
836        .saturating_add(members.saturating_mul(std::mem::size_of::<Series>()))
837}

839/// Charges the series a finished aggregate hands over, plus the queue they enter.
840///
841/// The queue's own backing is counted by the caller that appends to it, so what is added here is
842/// the series themselves and the vector that carries them; the two are charged together because
843/// the vector outlives the call that built it.
844fn charge_samples(
845    buffer: &mut NodeBuffer,
846    output: &[Series],
847    output_vec_bytes: usize,
848    queue_bytes: usize,
849) -> Result<()> {
850    let output_bytes = output.iter().fold(0usize, |bytes, series| {
851        bytes.saturating_add(series_bytes(series))
852    });
853    buffer.resize(
854        output_bytes
855            .saturating_add(output_vec_bytes)
856            .saturating_add(queue_bytes),
857    )
858}

860/// The rejection of a chunk that is not the layout this node folds.
861///
862/// The fold indexes its states by absolute grid position and by field, so a chunk of another field
863/// count or another grid would be folded into states that mean something else. `error` is what the
864/// series check reported, which says which of the two disagreed.
865/// Wraps the error of a chunk this node cannot fold.
866///
867/// Only a chunk that does not fit the schema is the node's own refusal; anything else is the
868/// kernel saying it does not compute this shape at all -- exporting native histogram state, for
869/// instance -- and a caller that falls back to another planner on `NotImplemented` still can.
870/// Wrapping that one in an `Execution` would deny it.
871fn folded_chunk(aggregate: &str, error: DataFusionError) -> DataFusionError {
872    match error {
873        DataFusionError::NotImplemented(_) => error,
874        error => DataFusionError::Execution(format!(
875            "the `{aggregate}` aggregate folds chunks bound to its own schema, and this \
876             one is not: {error}"
877        )),
878    }
879}
880
881/// The error for a fold that has already been finished.
882fn no_fold(aggregate: &str) -> DataFusionError {
883    DataFusionError::Execution(format!(
884        "the `{aggregate}` aggregate already finished its fold, so it takes no more input"
885    ))
886}
